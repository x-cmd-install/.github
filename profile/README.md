# x-cmd-install 👋

A daily, apples-to-apples snapshot of the 2,000+ open-source projects indexed by
[`x install`](https://x-cmd.com/install) — stars, releases, contributors, languages, and
how much has actually been happening lately.

Every repository here matches one package in the
[x-cmd/install](https://github.com/x-cmd/install) index. They're not mirrors of the
software; each is a small home for that project's history:

```
<software>/
  README.md          # points at the upstream repo: owner-repo: <owner>/<repo>
  data/260828.yml    # one snapshot per day
```

A snapshot carries stars, watchers, forks, releases, contributors, language byte
breakdown, and activity over rolling 30 / 90 / 180 / 360-day windows — merged PRs, open
PRs, closed issues, open issues, commits, releases. Everything lands together in
[**x-cmd-install-stat**](https://github.com/x-cmd-install/x-cmd-install-stat), so you can
diff a project against itself over time, or against any other project in the index.

## Contributions are very welcome 🙌

There's just one wrinkle worth knowing: the files under `data/` are regenerated by a
script every day, so an edit made directly there gets overwritten by the next run. Send it
one level up instead — same fix, and it improves every project in the index at once
instead of one.

| If you'd like to… | Here's the best place |
| --- | --- |
| add a package, or fix/remove one | an issue on [x-cmd/install](https://github.com/x-cmd/install/issues) |
| flag a number that looks wrong or missing | an issue on [x-cmd/install](https://github.com/x-cmd/install/issues) — these are genuinely useful, they usually point at a real gap in the collector |
| collect a new metric, or measure one better | a PR to [x-cmd/x-cmd](https://github.com/x-cmd/x-cmd) — the collector lives in its `repo` module |
| just have a look around | [x-cmd.com/install](https://x-cmd.com/install) · [x-cmd.com/mod/repo](https://x-cmd.com/mod/repo) |

Not sure which? Open an issue on [x-cmd/install](https://github.com/x-cmd/install/issues)
and we'll figure it out together.

## Why a script does the measuring

Ranking open-source projects by hand tends to smuggle in opinions — whoever writes the
entry quietly decides what counts. Letting one script gather the same fields for every
project, on the same schedule, keeps the comparison fair. It also means anyone can rerun
it and get the same answer.

That script is `x repo card`, part of the x-cmd `repo` module
([docs](https://x-cmd.com/mod/repo)). It works entirely through the GitHub API — one
GraphQL request plus one REST call per repository, no clone — and you can point it at
anything you like:

```sh
x repo card jqlang/jq              # colored table in a terminal
x repo card jqlang/jq > card.yml   # bare YAML when piped or redirected
```

# x-cmd-install 👋

给 [`x install`](https://x-cmd.com/install) 索引收录的 2000+ 开源项目做每日快照，口径统一、
可以横向比较 —— star、发布、贡献者、语言构成，以及最近到底有多少事情在发生。

本组织下每个仓库对应 [x-cmd/install](https://github.com/x-cmd/install) 索引里的一个软件。
它们不是软件的镜像，而是这个项目的一份小小的历史存档：

```
<software>/
  README.md          # 指向上游仓库：owner-repo: <owner>/<repo>
  data/260828.yml    # 每天一份快照
```

快照包含 star / watcher / fork / release / 贡献者数、语言字节构成，以及 30 / 90 / 180 /
360 天滚动窗口内的活跃度 —— 合并的 PR、开启的 PR、关闭的 issue、开启的 issue、提交、发布。
全部汇总到 [**x-cmd-install-stat**](https://github.com/x-cmd-install/x-cmd-install-stat)，
既可以看一个项目自己随时间的变化，也可以拿它和索引里任何其他项目对比。

## 非常欢迎参与 🙌

只有一点需要知道：`data/` 下的文件每天由脚本重新生成，直接改那里会被下一次运行覆盖掉。往上一层
提就好 —— 同样的修改，一次能让索引里所有项目都受益，而不只是一个。

| 你想… | 建议去 |
| --- | --- |
| 增加、修正、移除某个软件 | 在 [x-cmd/install](https://github.com/x-cmd/install/issues) 开 issue |
| 反馈某个数字看着不对或缺了 | 在 [x-cmd/install](https://github.com/x-cmd/install/issues) 开 issue —— 这类反馈很有价值，往往对应采集脚本里一个真实的漏洞 |
| 增加新指标，或把某个指标算得更准 | 向 [x-cmd/x-cmd](https://github.com/x-cmd/x-cmd) 提 PR —— 采集脚本在它的 `repo` 模块里 |
| 只是想逛逛 | [x-cmd.com/install](https://x-cmd.com/install) · [x-cmd.com/mod/repo](https://x-cmd.com/mod/repo) |

不确定该去哪？在 [x-cmd/install](https://github.com/x-cmd/install/issues) 开个 issue，
一起看看就好。

## 为什么让脚本来采集

人工给开源项目排序，容易不知不觉带进主观 —— 谁写条目，谁就悄悄决定了什么算数。让同一个脚本、
同一个节奏、对每个项目取同一组字段，比较才是公平的。而且任何人都可以自己重跑一遍，得到同样的结果。

这个脚本是 `x repo card`，x-cmd `repo` 模块的一部分（[文档](https://x-cmd.com/mod/repo)）。
它全程走 GitHub API —— 每个仓库 1 次 GraphQL + 1 次 REST，不做 clone —— 你也可以拿它看任何
你感兴趣的仓库：

```sh
x repo card jqlang/jq              # 终端里输出彩色表格
x repo card jqlang/jq > card.yml   # 管道或重定向时输出裸 YAML
```
